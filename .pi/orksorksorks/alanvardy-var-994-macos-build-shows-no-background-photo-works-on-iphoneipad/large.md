# Task

The macOS build of CheckStitch does not render the user-selected background photo on the main screen (only the flat `Color.systemBackground` fill shows), while the same build and settings render correctly on iPhone/iPad — a platform-specific regression. The likely mechanism is that `ContentView.swift` only applies `.containerBackground(.clear, for: .navigation)` under `#if os(iOS)`, and the macOS `NavigationStack` now paints an opaque container background that hides the `ZStack` photo layer drawn by `CheckStitch/BackgroundPhotoLayer.swift`; however the root cause is unconfirmed on a signed macOS run (`make build-mac-signed`), with several competing hypotheses that must be ruled out before the layout is changed. The fix must restore the photo (same fade opacity as iOS) on macOS across window resizes, add a test that reproduces the broken macOS branch / pins the fixed container-layout condition before the fix, pass `make test-unit` and the full gate (`bash scripts/test.sh`), and introduce no iOS/iPadOS rendering regression.

## Why LARGE

UNKNOWNS + CROSS_CUTTING (unknown ordering): the ticket itself enumerates four unverified candidate causes living in different subsystems — (1) macOS NavigationStack painting an opaque container background (the prime suspect, mirroring the iOS 26 fix), (2) the macOS `Color.clear.overlay { … }.ignoresSafeArea()` / `scaledToFill` wrapper collapsing on zero-intrinsic-size on macOS, (3) photo data never loading on macOS (`BackgroundImageStore.defaultDirectory` sandboxed path + network/Unsplash API), and (4) the KVS / `@AppStorage` path where `backgroundEnabled` may read false on macOS — so the approach is not confined to 0–2 known unknowns (M1 fails), the failing layer and the correct fix location (ContentView.swift vs BackgroundPhotoLayer.swift vs the KVS/data path) are undetermined until a debug session on a signed macOS run, and the change touches UI rendering across macOS/iOS platform targets plus a data/sync layer with a no-regression requirement — no existing single pattern carries it end to end.
