# Research Findings

## Q1: Side-effect seams for EventKit/Reminders and StoreKit

### Findings
- **Two protocol seams in Core.** `protocol ReminderDestinationTargeting: Sendable` (`@MainActor`) at `CheckStitchCore/Sources/CheckStitchCore/ReminderDestinationTargeting.swift:95-108`, doc-commented "injected so tests can drive denial/missing-list/save-failure without touching EventKit". Companion value types `ReminderListOption` (7-20), `ReminderListsSnapshot` (26-75), `ReminderAccessStatus` `.fullAccess/.notDetermined/.denied` (128-130). `ReminderListsSnapshot.resolve(_:)` returns `nil` when the stored `destinationListIdentifier` is gone → orchestrator reports `.destinationMissing` (50-58); `selectableOptions`/`pickerSelection` avoid offering the default twice (62-78). `ReminderRunOutcome` enum with `.errorMessage` mapping (80-113).
- **Older, narrower seam:** `protocol ReminderCreating: Sendable` with only `requestAccess()` + `create(...)` (`CheckStitchCore/.../ReminderCreating.swift:5-10`), consumed via `AppEnvironment.reminderCreator` (`Environment.swift:3-12`).
- **Concrete adapters.** `CheckStitch/EventKitReminderDestination.swift` — `@MainActor final class : ReminderDestinationTargeting` with `static let shared`, one long-lived `EKEventStore` (10-15); `accessStatus()` maps `EKEventStore.authorizationStatus(for:.reminder)` `.fullAccess/.notDetermined`, else `.denied` (22-29); `reminderLists()` enumerates `calendars(for:.reminder)` + `defaultCalendarForNewReminders()?` (31-39); `create(...)` re-resolves calendar by id, throws `ReminderDestinationError.listMissing` on TOCTOU deletion, saves with `save(reminder, commit: true)` (41-66), guarded by `#if !os(watchOS)`.
- **StoreKit seam kept out of Core** so Core stays StoreKit-free for watchOS: `protocol PurchaseProviding: Sendable` (`PurchaseProviding.swift:13-28`) with `offer()/currentEntitlement()/purchase()/restore()/startObserving(_:)`. `CheckStitch/StoreKitPurchaseService.swift` is the only StoreKit-importing type; `productID "app.alanvardy.CheckStitch.unlimited"`; uses `Product.products`, `Transaction.currentEntitlements` (verified + no revocation), `Transaction.updates`; throws `PurchaseError.productUnavailable/.unverified` (4-65). `PurchaseService.swift` is `@MainActor @Observable` orchestrator over `any PurchaseProviding`, caching verified entitlement in `PurchaseEntitlementCache` (`UserDefaults` key `purchase.verified.v1`), `start()` idempotent (10-104).
- **Run decision flow:** `CheckStitch/ChecklistReminders.swift` `enum ChecklistReminders` — production entry `create(from:)` uses `EventKitReminderDestination.shared` + `productionGate()` (8-21); Core `create(from:targeting:gate:)` decides: (1) `gate.reserveRun()` else `.purchaseRequired`; (2) `requestAccess()` else `.permissionDenied`; (3) `snapshot.resolve(...)` else `.destinationMissing`; (4) per-item `targeting.create(...)`, mid-loop throw → `.partiallyCreated`/`.failed` (24-74). `ChecklistRunViewModel.swift:15` wires store/targeting/counter/purchases/spinnerDuration and maps `.purchaseRequired` → paywall.
- **How tests drive it:** `TestFixtures.swift:22-47` `SpyReminderCreator: ReminderCreating`; `TestFixtures.swift:50-113` `SpyReminderDestination: ReminderDestinationTargeting` (records createdTitles/Notes/Priorities/ListIDs/Dates, `accessStatusValue`, `createFailureCount` to force mid-loop throws, `requestAccessCount`, `onRequestAccess`). `EventKitReminderDestinationTests.swift`/`EventKitReminderCreatorTests.swift` are crash-canaries over the global `sharedTestEventStore` (TestFixtures:18); one real round-trips `dueDateComponents` (no `save`). `ReminderListsSnapshotTests.swift` tests default-resolution logic. `ChecklistRemindersTests.swift` + `ChecklistRunViewModelTests.swift` (13-suite run-path cluster) drive denial/missing-destination/purchase-required/partial-failure through the spy. `PurchaseServiceTests.swift` drives `PurchaseService` through an injected `PurchaseProviding` fake.

## Q2: Non-Core app-side logic layer

### Findings
- **No protocols between app target and store types.** Every view model takes the concrete `@Observable final class` store directly. The only protocols in this layer are side-effect seams (KVS transport, EventKit, StoreKit), not for stores.
- `ChecklistStore.swift` is concrete `@Observable final class`, no `protocol`. Testability via **constructor injection**: `init(defaults:key:textEditDelay:now:)` — `defaults: UserDefaults = AppGroup.defaults`, `textEditDelay: Duration? = .milliseconds(300)` (nil = synchronous saves for tests), `now: () -> Date` (50-57). State: `private(set) var checklists/tombstones`, `envelope`, `canAcceptRemoteChanges` (20-26,104-110). Mutations (`create`, `duplicate`, `removeChecklists`, `moveChecklists`, import `insert`/`replace`) save via LWW-indexing writes.
- `ChecklistListViewModel(store: ChecklistStore)` forwards create/remove/move (`ChecklistListViewModel.swift:15-60`). `ChecklistRunViewModel(store:targeting:counter:purchases:spinnerDuration:)` (`ChecklistRunViewModel.swift:14-30`) — side-effect seams injected, `spinnerDuration` `.zero` for tests. `ChecklistImportExportViewModel(init(store:))` (10-50); `ChecklistImportSession(init(store:now:))` (43-60). `ChecklistSyncService(init(sync: any ChecklistSyncing, store: ChecklistStore, pushDelay:))` — the one place a protocol IS taken, but store still concrete (24-96). `BackgroundImageStore` uses internal `BackgroundImageFetching` seam + UUID temp `directory` (20-60); `BackgroundViewModel` wraps it (9-20). Settings: `SettingsViewModel` owns `SettingsBindings` bag + `SettingsDataActionQueue`, staged via `begin/_stage/takeStaged` (8-60).
- **Full-unit-testable in isolation:** `ChecklistMerge` — "no store, no seam, no I/O" (`ChecklistMerge.swift:6-9`).
- **How tested:** `ChecklistStoreTests.swift` uses isolated `UserDefaults` (`makeStore`, `suite.defaults`, `makeIsolatedDefaults`), reloads same suite to assert persistence (21,52-82). `ChecklistRunViewModelTests.swift` is `@MainActor`, real store with `makeIsolatedDefaults()`, `textEditDelay: nil`, `SpyReminderDestination`, `SpyPurchaseProvider`/`PurchaseEntitlementCache`, `.zero` spinner (7-49). Correlated suites per store/VM: `ChecklistStoreTests`, `ChecklistSyncServiceTests`/`CoordinatorTests`/`MessageTests`, `ChecklistMergeTests`, `ChecklistImportSessionTests`, `ChecklistImportExportViewModelTests`, `ChecklistRunViewModelTests`, `ChecklistListViewModelTests`, `BackgroundImageStoreTests`, `SettingsViewModelTests`, `WatchChecklistStoreTests`.

## Q4: Thick views & view-testing approach

### Findings
- Views are thin — they hold `@State`/`@AppStorage` UI slots, layout, and bindings that delegate mutations to `@Observable` view models or `ChecklistStore`. Heaviest is `ContentView.swift` (645 lines): injects seven environment objects (9-16), owns prefs + nav/editing `@State` (18-36), forwards callbacks (create 527-529, run 507-509, two-step remove 250-256); residual in-view logic is the `perform(_ action:)` dispatcher (594) and move-arrow translation (460-472).
- `ChecklistDetailView.swift` (349): reads store from `@Environment` (21); many `@State` slots for draft buffers/two-step gates (25-38); mutations via `Binding`s into store mutators (`destinationBinding/numberingBinding/titleBinding`). `ItemEditView.swift` (164): per-field `Binding`s through store mutators (104-150); date buffered via `RelativeDateDraft` seam (`commitDate` 158-163), no item-edit VM. `SettingsView.swift` (145): thin `Form` of links; export/import defer through `onExport`/`onImport` closures owned by `ContentView` (62,70).
- Extracted VMs (`@Observable`, `@MainActor`): `ChecklistListViewModel`, `ChecklistRunViewModel`, `SettingsViewModel`, `ChecklistImportExportViewModel`, `BackgroundViewModel`, `AppearanceViewModel`; heavy logic lives in the `@Observable` stores (e.g. `ChecklistStore.swift` 523 lines).
- **View-testing approach: primary = behaviour tests on VMs/stores** (`ChecklistRunViewModelTests` 160 lines, plus `ChecklistListViewModelTests`, `SettingsViewModelTests`, `BackgroundViewModelTests`, store suites). **Secondary = limited SwiftUI render tests** — `ViewRenderTests.swift:1-22` stages a store via `.environment(store)` and forces offscreen `ImageRenderer` (macOS `nsImage`/iOS `uiImage`).
- **Headless `body` limitation** documented in `ChecklistDetailViewTests.swift:1-14`: reading `body`/`.environment().body` fatal-errors without a live scene, so detail-view tests use `String(describing:)` to assert state-slot names/environment seams (`_store`, `isRemoveConfirmPresented` — 28-90) plus `ImageRenderer` render-oracles for `ChecklistDetailView` and `ItemRow` (72-75,165-167); `ItemEditView` covered by string-description + `RelativeDateDraft` logic tests (91-159,183-188).

## Q5: Test conventions & infrastructure

### Findings
- Unit suites in `CheckStitchTests/` (61 `.swift` files); single XCTest smoke `CheckStitchUITests/CheckStitchUITests.swift:3-9` (`runsForEachTargetApplicationUIConfiguration=false`, `continueAfterFailure=false`). `@testable import CheckStitchCore` and/or `@testable import CheckStitch`; ~50 files use `@testable`, 18 import Core.
- **Fixtures:** `TestFixtures.swift` — `makeItem` (7), `makeIsolatedDefaults` (UserDefaults wiped from `.standard`, 12-17), `@MainActor let sharedTestEventStore = EKEventStore()` kept alive globally because `EKReminder` holds a weak store ref (21-23), `SpyReminderCreator`, `SpyReminderDestination`. `StubBundle.swift:7-13` — `Bundle` subclass w/ fixed info dict, must restate `@unchecked Sendable` for Swift 6 + warnings-as-errors. `BackgroundTestFixtures.swift` — `jpegData` smallest valid 1×1 JPEG passing `isDecodableImage` without a network call (6-16), `FakeBackgroundFetcherError.unstubbedURL` (30-32). `LocalizationFixtures.swift` — `guardedCatalogs = ["App","Core","Watch"]`, `requiredKeys` per catalog (5-12). `LocalizationTestHelpers.swift` — `resolved(locale: .en)`, `String.en(key:bundle:)` (13-24), `Bundle.resourceBundle(named:in:)` (30-36).
- **`@MainActor` / platform gating:** test targets deliberately do NOT set `SWIFT_DEFAULT_ACTOR_ISOLATION`; suites opt in per-suite (`@MainActor struct ...Tests`) or on fixtures/doubles (`TestFixtures.swift:21,26,39`). macOS host only: `test-unit` runs `-destination 'platform=macOS'` (Makefile:69-83), no sim/signing (`CODE_SIGNING_ALLOWED=NO`).
- **Declared/run:** `struct` + behaviour-named `@Test func ...`, `#expect(...)`, `@Test(arguments:)` for data-driven. `Makefile`: `test: test-unit test-ui` (69); `test-unit` = `xcodebuild ... -destination '$(MAC_SIM)' CODE_SIGNING_ALLOWED=NO -only-testing:CheckStitchTests test` (71-83); `test-ui` = `build-for-testing` → `-only-testing:CheckStitchUITests test-without-building` on `$(SIM)` (this worktree's `.simulator_id`, never a bare name) (85-103). Destinations `SIM`/`MAC_SIM`/`WATCH_SIM` at Makefile:4-7; `WARNINGS_AS_ERRORS` passed to every leg.
- `scripts/test.sh` gate: `make build` → headless pre-boot → `make test` → `make build-mac` → `make watch-build` → `scripts/tests/run.sh` → `shellcheck` (AGENTS.md; test.sh:1-15). Handles missing vs unresolvable `.simulator_id`. `scripts/tests/run.sh` stubs `xcrun`/`defaults`/`make`/`open`/`osascript`; `new_stubs` (8-31), `run_case` tallies.

## Cross-Cutting Observations
- **Testability strategy is consistent and mature:** seam protocols for side effects (EventKit/StoreKit/KVS/network) + constructor injection (`UserDefaults`, `now`, `textEditDelay`, temp dir) + real `@Observable` concrete stores exercised directly with isolated defaults. New tests should slot into this pattern, not introduce new architecture.
- **App↔store has no protocol** — stores are concrete classes; the project's deliberate choice. Refactoring for testability would involve extracting logic seams rather than abstracting the store.
- **Untested sources are predictable:** mostly pure glue/delegate files (`MyApp`, `AppDelegate` already tested, adapters like `PhoneSyncAdapter`/`StoreKitPurchaseService`, thin views like `PaywallView`/`BackgroundSettingsView`/`ContentView`, and non-UI constants like `AppGroup`), plus `ChecklistSyncDiagnostics`/`ChecklistSyncing`/`Environment` in Core.
- **Sync diagnostics is the strongest Core gap** — `ChecklistSyncDiagnostics.swift` has zero tests and is pure logic by name.
- **View layer is deliberately thin and tested via VMs/render-oracles/string-description** — the headless `body` fatal-error is a documented architectural constraint.
