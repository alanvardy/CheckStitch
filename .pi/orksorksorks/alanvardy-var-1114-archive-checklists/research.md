## Q1: Checklist data model and ChecklistCodec encode/decode, version classification

### Findings
- `Checklist` (`Checklist.swift:145`) `struct Checklist: Identifiable, Codable, Hashable, Sendable`. Fields (:146-171): `id: UUID`, `name: String`, `items: [ChecklistItem]`, `destinationListIdentifier: String?`, `prefixesReminderNumbers: Bool`, `showsOnWatch: Bool`, `folderID: UUID?`, `modifiedAt: Date`, `revision: Int`, `itemOrder: [UUID]`, `orderRevision: Int`, `orderModifiedAt: Date`. Companion types in same file: `ChecklistItem` (:8), `ChecklistTombstone` (:341), `Folder` (:358), `FolderTombstone` (:405), `ChecklistEnvelope` (:419), `ChecklistCodec` (:476), `ChecklistSection` (:551).
- **Decode** (`ChecklistSwift.init(from decoder)` :214-241): required keys use `container.decode` (id, name :215-216); every additive/optional key uses `decodeIfPresent` with a `??` default — `items ?? []` (:214), `destinationListIdentifier` nil (:215), `prefixesReminderNumbers ?? false` (:218), `showsOnWatch ?? true` (:223, the only default-`true` stored field), `folderID` nil (:226), `modifiedAt ?? .distantPast` (:227), `revision ?? 0` (:228), `itemOrder ?? items.map(\.id)` (:229). Decode ends by re-entering the public init and `.normalizedOrder()` (:241).
- **Encode** (`Checklist.swift:245-267`): writes **every** key ("encoder writes every key" invariant :258). Only conditional shape: `folderID` when nil writes `encodeNil(forKey: .folderID)` (:262-264), never omits the key. Additive optional fields are encoded unconditionally.
- **Envelope** `ChecklistEnvelope` (:419-474): `version`, `deviceID`, `checklists`, `tombstones`, `folders`, `folderTombstones`; decode defaults absent arrays to `[]`, deviceID to `""` (:447-453); encode writes all six (:456-464). `contentEquals` ignores deviceID (:470-473) to decide whether a reconciled result must push back.
- **Versioning**: `ChecklistCodec.currentVersion = 5` (:478). `classify` (:504-536) probes `VersionProbe` first (never crash/partial-decode :505), outcomes (:489-494): `loaded` / `migratable(from, envelope)` / `unsupportedVersion` / `unreadable`. `case currentVersion → .loaded` (:510); v4/3/2/1 → `.migratable(from: N, envelope: previous)` loading verbatim (never restamp :513-526); unknown → `.unsupportedVersion` (:528-530); catch → `.unreadable` (:532-535). `decode(_ data)` (:539-544): returns checklists for loaded/migratable, `[]` for unsupported/unreadable.
- **Store handling** (`ChecklistStore.swift:72-99`): `.loaded` loads arrays with `canOverwriteStoredPayload = true` (:72-77); `.migratable` v1 `migrated(at:)` (:78-81), v2 `seededOrder()` (:82-85), v3+ verbatim (:86-89), always `canOverwriteStoredPayload = true` ("never stall migration" :90); `.unsupportedVersion` → empty arrays + **`canOverwriteStoredPayload = false`** (:91-96); `.unreadable` → empty arrays + `true` (:97-99). Store `envelope` (:114) always writes `version: currentVersion`; sync guard requires `remote.version == currentVersion` else `false` (`ChecklistStore.swift:588`).
- **Adding an additive field / not bumping version**: the `showsOnWatch`/`prefixesReminderNumbers` precedent was added with no bump (:178-182, :220-225): add a `CodingKeys` entry (:208-209), a `decodeIfPresent` + `?? default` line, an unconditional `encode` line, plus init/field. Not bumping is safe only for purely additive fields — old builds decode them as the default and re-encode. Risk only if a field is removed/renamed/re-typed/changed-default: the payload still classifies `loaded`, no guard, an older build could mis-read.

## Q2: ChecklistStore mutations and shared primitives

### Findings
- **State** (`ChecklistStore.swift:42-47`): `checklists`, `tombstones`, `folders`, `folderTombstones`; tombstones have no GC (:44-46). `canOverwriteStoredPayload` gate (:56-58, :91). `textEditDelay` 300 ms, `pendingSave: Task` debounce, injectable `now: () -> Date` (:59-66).
- **Coarse clock mutations** (revision+1 + `modifiedAt = now()`): `rename` (:232-243, sameName conflict excludes self), `setDestination` (:246-255), `setPrefixesReminderNumbers`/`setShowsOnWatch` — unchanged value = no-op guard (:258-296), `moveChecklist(toFolder:)` (:528-540). `moveChecklists` reorders array only, **no** revision bump (:479-490).
- **Tombstone creation**: `delete(id:)` removes + appends `ChecklistTombstone(checklistID, itemID: nil, deletedAt: now(), revision: removed.revision+1)` then `save()` (:611-617). `removeChecklists(at offsets:)` batch, one whole-checklist tombstone each, single save (:399-416). `removeItems` per-item tombstone (`itemID: removed.id`, revision+1) (:385-398). `importReplace` records the same whole-checklist tombstone then delete+insert in ONE save (:192-203). `deleteFolder` orphans members loose (each revision+1), one `FolderTombstone`, never checklist tombstones (:587-605).
- **Persist**: `scheduleSave()` (:636-646) — no textEditDelay → `save()` immediately, else debounced `Task`; `save()` (:648-665) cancels pending, guards `canOverwriteStoredPayload` else logs "Refusing to overwrite checklist payload written by a newer app version" and returns, `defaults.set(ChecklistCodec.encode(envelope), forKey: key)`, fires `onChange` unless `isApplyingRemote`; `flushPendingSave()` (:626-633) on screen dismiss / leave-foreground. Item edits bump item clocks only, never the checklist coarse clock (:325-384).
- **Name uniqueness**: `conflictingChecklist(named:)` → first `sameName` collider (:139-141); `sameName(a,b)]` case-insensitive on whitespace-trimmed strings (:321-325); `uniqueName(basedOn:taken:)` → base if free else `base 2`, `base 3`, … (:308-319). `create` (:148-152) uses `uniqueName` (revision 1); `duplicate` (:155-186) fresh-identity items revision 1.
- **Import**: `freshCopy(of:)` (:188-205) fresh local identity (new UUIDs, revision 1, `now()`), carries over `destinationListIdentifier`/`prefixesReminderNumbers`/`showsOnWatch`. `importInsert` (:208-218) = freshCopy + uniqueName (Keep Both, non-destructive). `importReplace` (:192-203) = tombstone + single save. Callers: `CheckStitch/ChecklistImportSession.swift`, `conflictingChecklist` (:71,83), `importInsert` (:134).
- **Merge entry**: `apply(remote:)` guards `canOverwriteStoredPayload` and `remote.version == currentVersion`, runs `ChecklistMerge.merge`, `normalizedOrder()` self-heal, idempotence guard, `isApplyingRemote=true` around save (:619-645).
- **Shape reference**: a whole-checklist field mutation follows rename/setDestination/toggles — `revision+=1` + `modifiedAt=now()` + unchanged-guard + structural `save()`. A permanent delete follows the tombstone (`revision+1`) shape. A soft archive would NOT tombstone (must stay restorable and survive merge); restore mirrors freshCopy/importInsert.

## Q3: ChecklistMerge convergence

### Findings
- **Entry**: `ChecklistMerge.merge(local, remote)` (`ChecklistMerge.swift:11-33`) composes `mergedTombstones`/`mergedChecklists`/`mergedFolderTombstones`/`mergedFolders`, applies tombstone suppression, returns envelope with `local.deviceID` (:25,31). Sole prod caller: `ChecklistStore.swift:589`.
- **LWW rule**: `wins(...)` (:257-265) — higher `revision`, tie-break newer `modifiedAt`, then lexicographically smaller `deviceID`. Deterministic + symmetric → both devices converge.
- **Checklist level** (`mergedChecklists` :130-191): result starts as local; remote-absent checklists appended wholesale with `.normalizedOrder()` (:134-137); when id on both, one `if wins(...)` copies the **entire coarse-clock record** (name/destination/prefixesReminderNumbers/showsOnWatch/folderID/revision/modifiedAt :164-171). **No per-field clocks for checklist-level fields** (:166-171). Ordering via orderRevision/orderModifiedAt + `reconciledOrder`/`reorder` (:174-185, :227-254).
- **Item level** (`mergedItems` :196-246): whole-item coarse win copied first (:217-221), then four independent per-field clocks for title/description/relativeDate/priority (`*Revision`/`*ModifiedAt`) (:223-243); defensive `merged.revision = max(...)` over adopted field clocks (:246) preserves the tombstone invariant.
- **Tombstones**: `mergedTombstones` (:40-66) union by `(checklistID, itemID)`, per-tombstone `wins`, deterministic sorted order; `deadChecklists` (itemID==nil) removed, item tombstones strip dead items (:28-37). Tombstones are unconditional suppressors — delete never resurrected (:5-8). Folder tombstones (:76-113).
- **Field absent reconciliation**: checklist-level reconcile is via **decode defaults**, not merge — `Checklist.init(from:)` defaults absent `destinationListIdentifier`→nil, `prefixesReminderNumbers`→false, `showsOnWatch`→true, `folderID`→nil (`Checklist.swift:334-360`). Item per-field clocks seed from the item coarse clock when absent (`Checklist.swift:103-116`).
- **Where a new boolean/date coarse field flows**: it shares the checklist coarse clock and is copied inside the same `if wins(...)` block alongside name/destination/prefixesReminderNumbers/showsOnWatch/folderID (`ChecklistMerge.swift:166-171`) — no version bump needed (additive default), matching the precedents. Only a per-field clock would need independent `if wins(...)` handling like the item `*Revision` blocks.

## Q5: UI surfaces and shared filtering conventions

### Findings
- **Core grouping helpers** (`Checklist.swift:563-634`): `isLoose(checklist, knownFolderIDs)` (:568-573) — true when no folderID or folderID names an unknown folder (cross-reference skew never drops a checklist); `sections` (:576-600) partitions folder buckets + trailing loose section; and the watch-only visible helpers — `visibleLooseChecklists` (:596-601, `isLoose && showsOnWatch`), `visibleChecklists(in folder)` (:604-609, `folderID == folder.id && showsOnWatch`), `visibleFolders` (:614-633, keeps folder with no members or ≥1 visible member). These three are the **only** place `showsOnWatch` filtering lives.
- **Watch** (`WatchChecklistViewModel.swift:25,30-31,36`): consumes the three `visible*` helpers at render time; phone keeps pushing hidden checklists (`Core doc :586-589`); `WatchChecklistListView.swift:10,19` renders, empty check `visibleFolders.isEmpty && looseChecklists.isEmpty`.
- **Main list (phone)** (`ContentView.swift` + `ChecklistListViewModel.swift`): `listVM.checklists` = `store.checklists` **unfiltered** (no showsOnWatch) (`ChecklistListViewModel.swift:17`); root empty state via `listVM.checklists.isEmpty` (`ContentView.swift:48-50`); `checklists(in folder: nil)` → loose via `ChecklistGrouping.isLoose`, else `folderID == folder.id` (`ChecklistListViewModel.swift:24-34`); enumeration: folders then loose (`ContentView.swift:463-470,589`); edit toolbar gated on `!listVM.checklists.isEmpty` (:68,75); `emptyState` (:684-696) — "No checklists" + create button.
- **Export** (`ContentView.swift:195-197`, `ExportChecklistsView.swift:23`): `store.checklists.map { ChecklistSelectionRow(...) }` unfiltered (:25-29); `ChecklistImportExportViewModel.swift` selection id-based, `exportSelected`/`shareSelected` filter `store.checklists.filter { exportSelection.contains($0.id) }` (:55-61,:72-79).
- **Settings**: `SettingsViewModel.swift:7` holds `SettingsBindings` bag, **does not enumerate checklists**; entry is a gear toolbar button; subscreens pushed via `NavigationLink` rows each with `.navigationTitle(...)` + `.settingsSubscreenLayout()`. `SettingsSubscreenLayout.swift:16-18` — macOS-only top-alignment modifier, iOS no-op; used by Background/Interface/ItemEdit/Privacy/About/PurchaseSettingsView (:78,67,82,40,34,56).
- **ChecklistDetailView** (`ChecklistDetailView.swift`): renders one checklist by id via `store.checklist(id: checklistID)` (:44,226,254,266,288); `showOnWatchBinding` (:277-284) get = `?.showsOnWatch ?? true`, set = `store.setShowsOnWatch`; mirrors numbering/destination bindings, all guarded on `.notFound`.

## Cross-Cutting Observations
- **Additive-optional-field pattern is uniform and precedent-backed**: `decodeIfPresent + ?? default`, unconditional `encode` (or `encodeNil` for optionals), no version bump — the `showsOnWatch`/`prefixesReminderNumbers`/`folderID` line all follow it. An archive flag/date would be the same shape.
- **Coarse vs per-field clocks**: checklist-level fields (name, destination, prefixesReminderNumbers, showsOnWatch, folderID) all share ONE coarse `revision`/`modifiedAt` and are copied atomically by the merge's single `if wins(...)` block (`ChecklistMerge.swift:166-171`). Only ChecklistItem has per-field clocks. So an archived flag/date belongs in the coarse block, picked up by merge with no codec/version change.
- **Uniqueness + import live in the store**: `uniqueName`/`conflictingChecklist`/`sameName` (rename/create/duplicate/import) and `freshCopy` (import identity) are the single chokepoints where "excludes archived" and "strips archived" would apply.
- **Enumeration is unfiltered everywhere except the watch**: the phone main list, export rows, entity query, and showOnWatch detail render all read `store.checklists` directly; the only filter today is `showsOnWatch` confined to the three `ChecklistGrouping.visible*` helpers used by the watch. Widget filters via id-resolution into the store's display model. Hiding archived checklists means touching each of these enumeration sites.
- **Run refusal is by absence**: `RunChecklistIntent` throws `checklistNotFound` when `store.checklist(id:)` is nil — an archived checklist can be refused with no new error string if the query/entity layer omits it or the intent guards it.
- **Localization cascade**: every new UI string must join `.xcstrings` (6 languages) + `LocalizationFixtures.requiredKeys` (+ `excludedIdentities`/`infoPlistTargets` only if applicable) and pass `scripts/l10n-check.sh` before `make test-unit`.
