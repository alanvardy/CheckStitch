# Task

Add JSON import and export of checklists to CheckStitch. Export: user multi-selects checklists, which are written as a `CheckStitch-<date>.json` document via `.fileExporter` / `ShareLink`, reusing the existing `ChecklistCodec` / `ChecklistEnvelope` so an export is a valid codec payload and the round trip is lossless — deciding explicitly what the export carries (checklists only is the sane default) and how `deviceID`/`tombstones` are treated on the way back in. Import: `.fileImporter`, decode with `ChecklistCodec.classify` (an unsupported version or unreadable file surfaces an error rather than importing nothing silently), detect conflicts via `ChecklistStore.sameName` (case-insensitive trimmed names), prompt per conflicting checklist to replace or keep (never overwrite without confirmation), and route every replace/insert through `ChecklistStore` so a replace records a tombstone and the change pushes via `ChecklistSyncService`. Tests cover export selection, the encode → classify → decode round trip, conflict replace, conflict skip, and rejection of corrupt or unsupported-version payloads.

## Why LARGE

CONVENTION_RISK + DESIGN_SIGN-OFF + CROSS_CUTTING: the ticket explicitly defers a design decision (export payload contents and deviceID/tombstone treatment on import), touches shared persistence/sync code (`ChecklistCodec`, `ChecklistStore` tombstone semantics, `ChecklistSyncService`) with backward-compat constraints (lossless round trip, unsupported-version rejection), and spans the data model/contract plus several UI surfaces (multi-select, file import/export, conflict prompts) in a new feature shape with no prior import/export ticket to carry it end to end.
