## Review

**What's correct (with evidence)**

- **Export→import round trip is sound.** `ChecklistExport.envelope` filters `store.folders` down to the ids actually referenced by the *selected* checklists (`Set(checklists.compactMap(\.folderID))`), deduped, empty tombstones, `deviceID: ""`. The envelope already carries `folders`/`folderTombstones` on v5 (Checklist.swift:506-514, decode at 523-525), so no schema/version change — matches the ticket.
- **No foreign device id / no tombstone resurrection.** `deviceID: ""` and empty tombstones are preserved; `decoded`'s migratable branch reconstructively carries `folders`/`folderTombstones` through (session:126-135).
- **resolveOrCreateFolder's no-`save()` is safe.** It only appends in-memory; the caller's `importInsert`/`importReplace` supplies the single `save()`. For every non-conflicting selected candidate that mints a folder, that same candidate is inserted and saved in loop 2 of `commit`, so a minted folder always has a checklist in the same save.
- **Pre-resolve loop and `decide()` agree.** `commit` pre-resolves only non-conflicting selected candidates (folder minted), conflicting ones are deferred to `decide`; `decide` calls `localFolderID` fresh, and `resolveOrCreateFolder` dedups by name, so a conflict decided later reuses the same candidate's folder (no duplicate). The name-based dedup means the pre-resolve-by-id path and decide-by-name path can't diverge (both resolve to the same-name local folder).
- **Keep Existing mints nothing.** The `.keepExisting` branch never calls `localFolderID` (session:168-169), and conflicting candidates are excluded from the pre-resolve loop, so a folder referenced only by a conflict is only minted when a decision actually imports — pinned by `keepExistingLeavesLocalFoldersUntouched` and `fileFolderTombstoneIsIgnored`.
- **Orphans land loose.** A `folderID` naming no file folder resolves `nil` (session:146-153 guard), and `folderMap[$0]` nil-reads as loose; pinned by `checklistWithOrphanFolderIDLandsLoose` and `replaceWithUnresolvedFileFolderLandsLoose`.
- **Same-name file-folder collisions collapse to one local folder** (both by id and by name) — pinned by `twoSameNamedFoldersInOneFileCollapseToOne` and `reImportingTheSameFileDoesNotDuplicateFolder`.
- **@MainActor / no mutation-after-await / no forced unwraps.** All session mutators (`stage`/`commit`/`decide`) are synchronous on the `@MainActor` session; `fileFolders` is written only in `stage`, read in `commit`/`decide`, and `stage()` resets `pending`, so a re-stage can't strand a stale `fileFolders`. `localFolderID` is guard-return-nil, no `!`.
- **Dictionary missing-key read idiom is valid.** `guard let fileFolderID, folderMap[fileFolderID] == nil, ...` relies on nil for a missing key; confirmed against the existing codebase pattern `if let existing = byKey[key]` (ChecklistMerge.swift:59) and `guard let index = indexByID[...]` (ChecklistMerge.swift:82).
- **Tests are non-vacuous.** The export tests assert *only*-referenced plus dedup (`["Groceries"]` from two members + one unreferenced), the store tests assert membership survives a reload, and the session tests assert concrete folder ids/revision/collapse rather than only names.

**Findings**

- **P2 — `decide` `.replace` mints a folder even when the local target vanished (edge partial-state).** session:160-165. `localFolderID(...)` runs as an argument *before* `importReplace`, so its folder-minting side effect happens even when `importReplace` returns `nil` (target deleted/renamed away between stage and decide — reachable if sync applies a remote delete while the conflict dialog is open). Result: a folder is appended to `store.folders` (unsaved), no checklist lands, and the next unrelated `save()` persists an empty folder — a folder-minted-without-checklist leak. The doc comment already treats this path as "counted as neither," so it's a known edge, but the folder mint is unintended there. Smallest fix: gate the resolution on the target index existing, e.g. resolve the folder only after confirming the replace target, or `guard` the nil case separately.
- **P2 — deviation #3 ("resolve only *selected* candidates' folders") has no direct test.** All five new session tests call `session.commit(selectedIDs: allIDs(session.candidates))`, i.e. every candidate selected. `keepExistingLeavesLocalFoldersUntouched` covers the *conflicting-but-unselected-within-commit* shape, but nothing pins that an *unticked* candidate's referenced folder is never minted. Add a test that stages a two-folder/two-candidate file, commits with only one candidate selected, and asserts the unselected candidate's folder was not minted.
- **P2 (documented tradeoff, worth surfacing)** — name-based matching means an imported folder gets a fresh local id, so under LWW sync (merge is by id, ChecklistMerge.swift:82) a same-name folder can coexist as two folders across devices. `renamedLocalFolderGetsANewFolderOnImport` documents this; it's an accepted limitation, not a bug.
- **P2 (note)** — a selected checklist whose `folderID` names a folder not present in the passed `folders` list (e.g. referencing a deleted/folderTombstoned folder) is silently exported without its folder and lands loose on import. Consistent with the "orphan lands loose" design, but means membership in a deleted folder is silently dropped rather than erroring.

**Merge verdict: OK with notes.** No blockers. The folder round trip is sound, error/partial-state handling is mostly deliberate and safe, Swift hazards are clean, and the tests genuinely pin the claimed behavior. The `.replace`-vanished-target folder mint and the missing unticked-candidate test are the two worth addressing.
