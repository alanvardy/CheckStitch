## Q1: Existing file-import data flow (bytes → store)

### Findings
- **Entry is a SwiftUI file picker, JSON-only.** `CheckStitch/ContentView.swift:178-183` — `.fileImporter(allowedContentTypes: [.json])` yields a `URL`; `.success` → `importExportVM.importFile(at: url)`, `.failure` → `importFailed`. `.fileImporter` declared again at `ContentView.swift:207-216`.
- **Only read path is `importFile(at url:)`** — there is no no-argument variant (`CheckStitch/ChecklistImportExportViewModel.swift:67-85`). Security-scoping: the read is wrapped in `url.startAccessingSecurityScopedResource()` / `defer { url.stopAccessingSecurityScopedResource() }` (`:69-70`); only `Data(contentsOf: url)` sits inside the pair (`:73-76`).
- **Decode pipeline**: `importFile(at:)` builds `ChecklistImportSession(store:)` and calls `session.prepare(data:)` (`ChecklistImportExportViewModel.swift:79-85`). `ChecklistCodec.classify(_:)` at `CheckStitchCore/Sources/CheckStitchCore/Checklist.swift:395-424`: probes `version` via `VersionProbe` before full decode (`:421`) → `.loaded(envelope)` (v=4), `.migratable(from: 3|2|1, envelope:)`, `.unsupportedVersion` (`:412-414`), or `.unreadable` (decode throw). `currentVersion = 4` (`:368`).
- **`prepare(data:)`** (`CheckStitch/ChecklistImportSession.swift:60-102`): resets `pending`/`summary`; switches on `classify`; `.migratable` normalisation at `:85-93` (v1 `migrated(at:)`, v2 `seededOrder()`, v3 via `default` → unchanged).
- **Candidate/conflict model**: `ChecklistImportCandidate` (`ChecklistImportSession.swift:27-32`) = `id: UUID`, `checklist`, `conflicting: Checklist?` (nil = inserted immediately). Conflict = **name collision** via `store.conflictingChecklist(named:)` (`CheckStitch/ChecklistStore.swift:125-128`), trimmed + case-insensitive `sameName` (`ChecklistStore.swift:283-286`).
- **FIFO**: `prepare` loops incoming checklists (`ChecklistImportSession.swift:94-106`); non-conflicting → `store.importInsert` (`summary.inserted`); conflicts append to `pending` in file order. `pending` is `@Observable` for the dialog.
- **Decision application**: `decide(_:for:)` (`ChecklistImportSession.swift:106-119`) removes from `pending` then: `.replace` → `store.importReplace(id:with:)` (`ChecklistStore.swift:209-220`, tombstone + single `save()`, counts only if target still exists); `.keepBoth` → `store.importInsert` auto-disambiguates via `uniqueName` (`ChecklistStore.swift:195-206`, `summary.keptBoth`); `.keepExisting` → no mutation (`summary.keptExisting`).
- **VM FIFO driver**: `importFile` sets `conflict = session.pending.first` (`ChecklistImportExportViewModel.swift:86`); `decide(_:)` (`:90-96`) / `dismissConflict()` (`:100-105`, forces `.keepExisting`) clear + apply + `advanceConflict()` (`:114-117`) re-presents next `pending.first` in a `Task` until the queue drains.
- **Dialog**: `ContentView.swift:186-192` `confirmationDialog("Name conflict")` with Replace / Keep Both / Keep Existing(cancel).
- **Fresh local identity on import**: `freshCopy` (`ChecklistStore.swift:181-193`) and `importInsert` (`:195-206`) mint new checklist AND item `UUID`s, `revision: 1`, stamp `now()`, drop imported `destinationListIdentifier`; `importReplace` records a tombstone then fresh-inserts.
- **ImportSummary** (`ChecklistImportSession.swift:40-45`): `inserted / replaced / keptBoth / keptExisting`. **ChecklistImportError** (`:6-22`): `.unreadable` ("This file isn't a CheckStitch export."), `.unsupportedVersion` ("…newer version of CheckStitch."), thrown in `prepare` (`:98, :100`). VM maps to `importErrorMessage` (`ChecklistImportExportViewModel.swift:79-84`); read errors → system `.localizedDescription` (`:76-78`).
- **Formats**: `.json` only (content type + decode). v4 loaded, v1-3 migratable, unknown-version / undecodable → hard error; any failure leaves store untouched.

## Q2: Platform intent / share / receive mechanism

### Findings
- **There is no OS file-/share-target wiring.** No `onOpenURL`, no `CFBundleURLTypes`, no `application(_:open:)`, no `UTType` import registration. The only receive paths are (a) AppIntents/AppShortcuts for Siri/Shortcuts and (b) the in-app `.fileImporter` picker (user-operated, not OS-driven).
- **App entry/delegates have no receive handlers**: `CheckStitch/MyApp.swift:8` `@main struct MyApp: App`; iOS `AppDelegate` via `@UIApplicationDelegateAdaptor` (`:12`), macOS `MacAppDelegate` via `@NSApplicationDelegateAdaptor` (`:16`). `CheckStitch/AppDelegate.swift` — iOS only applies appearance/orientation (`:10-64`), macOS only re-clamps window frames (`:71-end`). Neither implements `application(_:open:)`.
- **Intent registration**: `CheckStitch/Intents/CheckStitchShortcuts.swift:3-17` — `AppShortcutsProvider` advertising `RunChecklistIntent()` and `ListChecklistsIntent()` (natural-language `phrases`, `shortTitle`/`systemImageName`); the AppIntents framework auto-catalogs them (no manual registration).
- **`ChecklistEntity.swift:7`** — `struct ChecklistEntity: AppEntity`, `id` = `Checklist.id.uuidString`; `ChecklistEntityQuery` (`:31`) with `entities(forIdentifiers:)`, `entities(matching:)`, `suggestedEntities()` (`:41-65`); each call builds a fresh `ChecklistStore(defaults: AppGroup.defaults)` when not injected (`:36`).
- **`ListChecklistsIntent.swift:8-20`** — `AppIntent`, `openAppWhenRun = false`; `perform()` maps suggested names into an `IntentDialog` via `ListChecklistsDialogue.message(for:)` (`:29-45`).
- **`RunChecklistIntent.swift`** — `AppIntent` with `@Parameter(title: "Checklist") var checklist: ChecklistEntity` (`:30`); `perform()` (`:48-86`) does an **explicit permission pre-check before any create**: `targeting.accessStatus()` (`.notDetermined`/`.denied` return dialog results, never prompt from inside an intent); `.fullAccess` → `ChecklistReminders.create(from:targeting:)`. `RunChecklistIntentError.checklistNotFound` guard (`:8-14, :58-62`). `targeting` defaults to `EventKitReminderDestination.shared` (`:55`).
- **The only file-receive surface is the user-picked importer** (`ContentView.swift:171-180`; `ChecklistImportExportViewModel.swift:67-85`). `CheckStitch/ChecklistExportDocument.swift:9` declares `readableContentTypes: [UTType] { [.json] }` but the `init(configuration:)` read path (`:17-24`) is "only declared to satisfy FileDocument — the app never opens a document this way."
- **Validation/security**: file reads are security-scoped; **format validation lives entirely in `ChecklistImportSession`/codec**, not in a share/receive layer. Prior var-1019 research corroborates: no `onOpenURL`, `CFBundleURLTypes`, user activities, or notifications (`.pi/.../alanvardy-var-1019-add-app-intents/research.md:43`).
- **Entry-point answer**: iOS/macOS never hands the app a file directly — the only file entry is the user-operated `.fileImporter` sheet. Intent entry is Siri/Shortcuts invoking the catalogued intents; `perform()` may cold-start, which is why `RunChecklistIntent` never prompts for permission (status-only pre-check).

## Q3: Checklist → Reminders creation flow

### Findings
- **Two creation paths exist.**
- **A. `ChecklistCreator` (Core, simpler)** — `CheckStitchCore/Sources/CheckStitchCore/ChecklistCreator.swift`: holds `reminders: ReminderCreating`, `now`, `calendar`, `prefixNumbers: Bool` (`:25`). `create(from items:) -> ChecklistCreationOutcome` (`:36`): `guard try await reminders.requestAccess() else { return .permissionDenied }` (`:38`); loops `for item in items where !item.isBlank` (`:43`), bumps `position` only after blanks dropped, `reminders.create(title:, dueDateComponents:)` (`:47`); `.created(count:)` or `.failed(error.localizedDescription)` (`:52`). Numbering via `ChecklistTitleNumbering.title(_ title, position, numbered)` (`:17`): `numbered ? "<position>: <title>" : title`.
- **`ReminderCreating` protocol + `EventKitReminderCreator`** — `CheckStitchCore/.../ReminderCreating.swift`: protocol (`:11`) = `requestAccess() async throws -> Bool`, `create(title: String, dueDateComponents: DateComponents?) async throws` (no destination/notes/priority). `EventKitReminderCreator` (`:30`) `@MainActor`, wraps one long-lived `EKEventStore`; `requestAccess` → `eventStore.requestFullAccessToReminders()` (`:36`); `create` (`:39`) builds `EKReminder`, sets `.title`, `.calendar = eventStore.defaultCalendarForNewReminders()` (`:42`), sets `.dueDateComponents`, `eventStore.save(reminder, commit: true)` scoped `#if !os(watchOS)` (`:46-48`).
- **B. `ChecklistReminders` (production entry, richer)** — `CheckStitch/ChecklistReminders.swift`: `create(from checklist, targeting:) -> ReminderRunOutcome` (`:26`). **Validation before any create**: `requestAccess()` (`:28`) → `reminderLists()` snapshot (`:29`) → `guard let destination = snapshot.resolve(checklist.destinationListIdentifier) else { return .destinationMissing }` (`:30`; comment "All-or-nothing: validate existence before the first create.").
- Loop `for item in checklist.items where !item.isBlank` (`:33`), `position += 1`, `dueDateComponents = item.dueDateComponents(today: Date())` (`:38`), then `targeting.create(title: ChecklistTitleNumbering.title(...), notes: item.hasDescription ? item.description : nil, priority: item.priority, in: destination, dueDateComponents:)` (`:39-46`). Error handling: `.partiallyCreated(created, total, reason)` if `created > 0` (TOCTOU mid-loop, `:57`), else `.failed` (`:61`).
- **Destination seam** — `CheckStitchCore/.../ReminderDestinationTargeting.swift:58` protocol: `requestAccess()`, `accessStatus() -> ReminderAccessStatus`, `reminderLists() -> ReminderListsSnapshot`, `create(title, notes, priority, in list, dueDateComponents)`. `ReminderListsSnapshot` (`:28`): `defaultIdentifier` missing == failure (`resolve` nil → `.destinationMissing`); `selectableOptions` excludes system default (`:48`); `pickerSelection(for stored:)` maps default→nil (`:57`). `ReminderRunOutcome` (`:64`): `created/destinationMissing/permissionDenied/partiallyCreated/failed` with `errorMessage` (`:75`).
- **`EventKitReminderDestination`** (`CheckStitch/EventKitReminderDestination.swift:14`) `@MainActor`, `static let shared` (`:17`). `accessStatus` (`:28-35`) switches `EKEventStore.authorizationStatus(for: .reminder)` — only `.fullAccess`, `.notDetermined`; else denied. `reminderLists` (`:37`) enumerates `calendars(for: .reminder)`, `defaultIdentifier: eventStore.defaultCalendarForNewReminders()?.calendarIdentifier` (`:45`). `create` (`:49`) **re-resolves by identifier** — `guard let calendar = ...first(where: { $0.calendarIdentifier == list.id }) else { throw ReminderDestinationError.listMissing }` (`:51-54`, TOCTOU guard), sets title/notes/calendar/`priority.rawValue`/dueDate, `save(reminder, commit: true)` (`#if !os(watchOS)`).
- **Per-item constraints**:
  - *Blank titles dropped*: `isBlank` = title trimmed of whitespace/newlines empty (`Checklist.swift:117`); both `ChecklistCreator` (`:43`) and `ChecklistReminders` (`:33`) filter `where !item.isBlank`.
  - *Prefix numbering*: after dropping blanks, `position += 1`; `ChecklistTitleNumbering.title` (`ChecklistCreator.swift:17`) → `"<position>: <title>"` when `prefixNumbers` (from `checklist.prefixesReminderNumbers`, `Checklist.swift:186`).
  - *Due date*: `dueDateComponents(today: Date, calendar)` (`ChecklistItem+DueDate.swift:9`): nil if `relativeDate` nil; else `DateComponents([.year,.month,.day])` from `calendar.date(byAdding: .day, value: relativeDate, to: startOfDay(today))`. Date-only.
  - *Description→notes*: only when `hasDescription` = trimmed description non-empty (`Checklist.swift:105`), as `notes` (else nil).
  - *Priority*: `ChecklistItemPriority` raw values `none=0,low=9,medium=5,high=1` (`ChecklistItemPriority.swift:8-11`) written raw to `EKReminder.priority`; declaration order is menu order.
- Note: `accessStatus()` (read-only, status-only) exists for intent paths wanting a clean fail without prompting; the create path itself calls `requestAccess()`.

## Q5: Export wire format, round-trip, and import test patterns

### Findings
- **Wire format is JSON.** `ChecklistCodec.encode(_:)` → `JSONEncoder().encode(envelope)` (`Checklist.swift:394`); `classify`/`decode` probe with `JSONDecoder`. `currentVersion = 4` (`Checklist.swift:377`).
- **`ChecklistEnvelope`** (`Checklist.swift:323-369`): `version: Int`, `deviceID: String`, `checklists: [Checklist]`, `tombstones: [ChecklistTombstone]`; `decodeIfPresent` defaults (`deviceID`→"", `checklists`→[], `tombstones`→[]) so v1 payloads load; `contentEquals` ignores `deviceID` (`:361`).
- **`ChecklistCodec.Outcome`** (`Checklist.swift:381-393`): `.loaded / .migratable(from:, envelope:) / .unsupportedVersion / .unreadable`. `classify` (`:399-436`) probes `VersionProbe {version}`; `==4`→`.loaded`, `3|2|1`→`.migratable` (loaded verbatim, never restamped), else `.unsupportedVersion`; catch→`.unreadable`. `decode` (`:440-447`) maps `.unsupportedVersion`/`.unreadable` → `[]`.
- **Item encodings** (`Checklist.swift:8, Codable`, keys `:87`): id, title, description, modifiedAt, revision, relativeDate, per-field clocks (title/description/relativeDate/priority each Revision+ModifiedAt), priority. Decode additive-optional tolerant: absent `description`→"" (`:111`), `modifiedAt`→`.distantPast`, `revision`→0, `relativeDate` optional (`:117`), per-field clocks seed from coarse clock (`:121-132`), absent `priority`→`.none` (`:140`). Encode writes every key (comment `:150`). `ChecklistItemPriority` unknown raw value throws → whole payload `.unreadable` (closed domain).
- **`ChecklistExport`** (`CheckStitchCore/.../ChecklistExport.swift`): `envelope(checklists:)` (`:8-12`) builds v=`currentVersion`, `deviceID:""`, `tombstones:[]`; `data(checklists:)` (`:16`) → `encode`; `filename(for:calendar:)` (`:22-32`) → `CheckStitch-yyyy-MM-dd` (en_US_POSIX). `ChecklistExportDocument` (`CheckStitch/ChecklistExportDocument.swift:8`) is the `FileDocument` wrapper; `ContentView.swift:173` passes `defaultFilename: ChecklistExport.filename()`.
- **Test patterns**:
  - `ChecklistCodecTests.swift` — **XCTest** `final class`, `@MainActor` (`:6-7`). (a) literal byte-sample JSON via `Data(#"..."#.utf8)` for v1/v2/v3/v4 (`:30, :45, :59, :126`); (b) programmatic `ChecklistEnvelope(...)` + `classify` round-trips (`:11`, `:106`, `:156`); asserts `"itemOrder"`/`"description"` key presence.
  - `ChecklistExportTests.swift` — XCTest `@MainActor` (`:6-7`); fixtures `makeChecklists()`/`selectedPair()` (`:9-23`); round-trip `data`→`classify`==`.loaded` then name/order/description/relativeDate/deviceID/tombstone asserts (`:25-53`), priority (`:44`), empty selection (`:63`), filename regex/default (`:77`) + fixed-date determinism (`:83`), `testFileWrapperCarriesEncodedBytes` (`:93`).
  - `ChecklistImportSessionTests.swift` — **Swift Testing** (`struct`/`@Test`/`#expect`), `@MainActor` (`:7`); fixture `makeSession()` + `payload(...)` (`:13`); covers non-conflict insert (`:18`), conflict left pending (`:30`), `unsupportedVersion` + store untouched (`:48`), unreadable (`:70`), migratable v1/v2 (`:87`), three decisions (`:108/:141/:170`), re-import stability (`:181`), priority preserved (`:202`); `#expect(throws:)` for errors.
  - `ChecklistImportExportViewModelTests.swift` — Swift Testing `@MainActor` (`:8`); fixtures `makeStore(names:)`/`writeTempFile(_:)` (`:9-21`); export selection→document (`:25`), empty selection (`:39`), read-failure (`:52`), format-failure message (`:65`), FIFO queue via `viewModel.decide` + `await Task.yield()` (`:77`).
  - `@Test(arguments:)` used in **none** of these four suites; it appears elsewhere (e.g. `ChecklistItemTests.swift:14,19,...`, `ChecklistItemDateTests.swift:22`, `ChecklistCreatorTests`, etc.).
- **Module split**: envelope/codec/export type / creator / targeting protocols live in the `CheckStitchCore` SPM package; `ChecklistImportSession`, `ChecklistExportDocument`, `ChecklistSyncService`, the import-export view model, and `ChecklistReminders`/`EventKitReminderDestination` live in the app target `CheckStitch/`.

## Cross-Cutting Observations
- **No platform file-receive or share-target seam exists** (Q2): no `onOpenURL`, `CFBundleURLTypes`, `application(_:open:)`, or `UTType` registration. Every inbound file today is user-picked via SwiftUI `.fileImporter`; format/version validation lives entirely in the core codec/import session, not in a receive layer.
- **The checklist→Reminders path is destination-aware and all-or-nothing-validated** (Q3): `ChecklistReminders` resolves the checklist's `destinationListIdentifier` before the first create; `ChecklistCreator` is a simpler non-destination path. Blank titles are always dropped and prefix numbering is a shared `ChecklistTitleNumbering` policy.
- **Selection UI precedent is the export checkmark sheet** (Q4): a `Set<UUID>` + pure `toggled` helper in `ExportChecklistsView.swift`; there is no generic selectable-list and no positive import/export success feedback.
- **Import writes fresh local identity** (Q1): new UUIDs, revision 1, dropped `destinationListIdentifier`; name-collision conflict handling is FIFO + three choices.
- **Testing is split by framework**: XCTest suites for codec/export (byte-sample fixtures, `@MainActor` class), Swift Testing (`@Test`/`#expect`) for import session + view model, `@Test(arguments:)` used sparingly elsewhere.

## Open Areas
- **"Share Sheet" reception seam does not exist today** (Q2): research found no existing mechanism by which the OS or another app hands a shared file or URL into CheckStitch. How a shared checklist file should enter the app (the ticket's import seam) is not established by any current code — this is the primary gap for the design phase.
- Line anchors inside the large `ChecklistStore.swift` beyond conflictedInsert/importReplace/freshCopy/uniqueName/sameName weren't fully enumerated (large file).
- The Q4 report notes potential macOS quirks (a sheet-nested `.fileExporter` "never presents on macOS"); the exact macOS trigger/conditions were not fully established.
