# Research Findings

## Q1: End-to-end flow that creates reminders for a checklist's items

### Findings
- **Public entry**: `ChecklistReminders.create(from checklist: Checklist)` at `CheckStitch/ChecklistReminders.swift:12-13` delegates to `create(from:, targeting: EventKitReminderDestination.shared)`. The orchestration body is `:16-40`: a single `do { … } catch { … }` around a `ReminderDestinationTargeting` seam.
- **Permission**: `guard try await targeting.requestAccess() else { return .permissionDenied }` (`ChecklistReminders.swift:18`). The real adapter's `requestAccess()` is `try await eventStore.requestFullAccessToReminders()` returning `Bool` (`CheckStitch/EventKitReminderDestination.swift:16-18`) — a status/attempt call with **no user prompt**; `false` → `.permissionDenied`, a throw escapes to the catch → `.failed`. There is no separate authorization-status read anywhere in the run path (see Open Areas).
- **Destination choice**: `let snapshot = try await targeting.reminderLists()` (`:19`) then `guard let destination = snapshot.resolve(checklist.destinationListIdentifier)` (`:20-23`). `ReminderListsSnapshot.resolve` (`CheckStitchCore/Sources/CheckStitchCore/ReminderDestinationTargeting.swift:31-37`) maps stored `nil` → the default identifier; a stored id or the default that no longer exists → `nil` → `.destinationMissing`. This runs **before the first create** (all-or-nothing, comment at `ChecklistReminders.swift:21`).
- **Per-item loop**: `for item in checklist.items where !item.isBlank` (`:25`), per item: `item.dueDateComponents(today: Date())` (`:29`, pure Core, date-only, device-local today) then `targeting.create(title:, notes: item.hasDescription ? item.description : nil, in: destination, dueDateComponents:)` (`:30-34`); `created += 1` only after a successful await (`:35`). Returns `.created(count:)` (`:37`).
- **Save & TOCTOU**: `EventKitReminderDestination.create` (`EventKitReminderDestination.swift:30-48`) re-resolves the list by id at save time (`:33-35`); if it vanished mid-loop it throws `ReminderDestinationError.listMissing`, which aborts the loop — items created earlier in the loop are already committed, and the count is discarded (`.failed` carries no count). Then sets `reminder.title`, `if let notes { reminder.notes = notes }`, `reminder.calendar`, `if let dueDateComponents { … }`, and `eventStore.save(reminder, commit: true)` guarded by `#if !os(watchOS)` (`:45-47`).
- **Outcome values**: `enum ReminderRunOutcome` (`ReminderDestinationTargeting.swift:58-62`) = `.created(count: Int)` / `.destinationMissing` / `.permissionDenied` / `.failed(String)`. `errorMessage` (`:66-73`): `.destinationMissing` → "That list no longer exists; no reminders were created." (`:69`), `.permissionDenied` → "CheckStitch doesn't have permission to access Reminders; no reminders were created." (`:70`), `.failed(m)` passes `m` through (`:71`) — any thrown error's `localizedDescription` (`ChecklistReminders.swift:39-40`); `.created` → `nil`.
- **Partial-creation state**: `.failed` is the only outcome reachable with N>0 items already created (mid-loop throw); `destinationMissing` and `permissionDenied` are returned before any create by construction. `isBlank` items are silently skipped, not errors (`Checklist.swift:89-91`, loop at `ChecklistReminders.swift:25`).
- **Consumer**: the only UI consumer is `ContentView.createReminders(for id: UUID)` (`CheckStitch/ContentView.swift:373-395`): guard `!creating.contains(id)` + fresh `store.checklist(id:)` (`:376`), double-tap protection, ≥1 s spinner, `await ChecklistReminders.create(from: checklist)` (`:382`), switch at `:385-392`: `.created` → 1 s transient checkmark (`:386-389`); `.destinationMissing/.permissionDenied/.failed` → `runErrorMessage = outcome.errorMessage` (`:390-392`).

## Q2: ChecklistStore surface, identity and lifecycle of rename/delete

### Findings
- **Enumeration/lookup**: `private(set) var checklists: [Checklist]` — the only read surface (display order, no sort) (`CheckStitch/ChecklistStore.swift:20`); `checklist(id: UUID) -> Checklist?` (`:101-103`); `conflictingChecklist(named:)` — first trimmed, case-insensitive name match, import's conflict primitive (`:106-108`); computed `envelope`, `canAcceptRemoteChanges`, `deviceID` (`:86-96`); persistence key `"checklists.v1"` in `UserDefaults` + per-install `"checklist.deviceID"` (`:58`, `:99`).
- **Mutations**: `create(name:)` always succeeds, name disambiguated (`"New checklist"`, `"New checklist 2"`, …) (`:114-122`); `duplicate(id:, name:)` fresh item UUIDs, `nil` when source gone (`:134-150`); `rename(id:, to:) -> .renamed/.nameTaken/.notFound` (`:213-225`); `setDestination(_ identifier:, for:) -> .updated/.notFound` (`:230-239`, nil = system default); item ops `addItem`/`updateItem`×3/`updateItemDescription`/`removeItems`/`moveItems` (`:292-336`); `importInsert`/`importReplace` (`:176-203`); `delete(id:)` (`:339-346`); `flushPendingSave()` 300 ms-coalesced text save (`:402-407`); `apply(remote:)` sync merge (`:374-395`).
- **Identity**: `public let id: UUID` is stable and immutable (`CheckStitchCore/Sources/CheckStitchCore/Checklist.swift:92,100`); rename bumps only `name`, `revision += 1`, `modifiedAt` (`ChecklistStore.swift:219-224`) — the same UUID survives rename on every device and stays the merge key (`Checklist.swift:117-120` "a rename or a destination change bumps them").
- **Delete**: removes the checklist and appends `ChecklistTombstone(checklistID:, itemID: nil, deletedAt:, revision: removed.revision + 1)` (`ChecklistStore.swift:339-346`); item deletes carry `itemID` (`:269-284`). Tombstones are permanent, grow-only ("There is no retention/GC yet, so this only grows", `:22-25`), part of the envelope (`:86-91`) and sync wire format (`Checklist.swift:265-281,291-293`).
- **Sync interplay**: merge unions tombstones by `(checklistID, itemID)` — winner = higher `revision`, then newer `deletedAt`; dead checklists/items suppressed so a deletion can't be resurrected (`CheckStitch/ChecklistMerge.swift:11-31`); rename/destination LWW by `revision → modifiedAt → device id` (`:59-73`).
- **Consumers**: ContentView list `ForEach(store.checklists)` (`ContentView.swift:286`), empty state `:49`, run guard `store.checklist(id:)` (`:376`); ChecklistDetailView rename/delete/destination picker (`ChecklistDetailView.swift:176-183,156-165,218-236`), `.onDisappear` flush (`:136`); ExportChecklistsView list (`:33`); import conflict/insert/replace (`ChecklistImportSession.swift:88,94,111`); sync wires `store.onChange` (`ChecklistSyncService.swift:48`), launch reconcile `apply`+push (`:109-131`).

## Q3: Per-item / per-checklist settings onto a created reminder

### Findings
- **Two creation paths exist**. Path A (production): `ChecklistReminders` + `EventKitReminderDestination`, used by `ContentView.swift:382` and the iOS sync coordinator (`MyApp.swift:67`). Path B (legacy, test-only today): `ChecklistCreator` (`CheckStitchCore/Sources/CheckStitchCore/ChecklistCreator.swift:18-50`) over the `ReminderCreating` seam (`ReminderCreating.swift:9-43`), constructed only by `ChecklistViewModel` (`ChecklistViewModel.swift:13,37-56`), itself constructed only by tests and `AppEnvironment` (`Environment.swift:6-10`).
- **title → reminder.title**: both paths pass `item.title` (`ChecklistReminders.swift:31`; `ChecklistCreator.swift:40`) → `reminder.title = title` (`EventKitReminderDestination.swift:38`; `ReminderCreating.swift:36`). Blank/whitespace titles skipped in both (`ChecklistItem.isBlank`, `Checklist.swift:89-91`).
- **description → reminder.notes**: only Path A: `notes: item.hasDescription ? item.description : nil` (`ChecklistReminders.swift:32`), `hasDescription` = non-whitespace (`Checklist.swift:80-82`); adapter `if let notes { reminder.notes = notes }`, nil leaves unset (`EventKitReminderDestination.swift:39`). **Not copied in Path B** — `ReminderCreating.create` has no notes parameter (`ReminderCreating.swift:13`), `ChecklistCreator` never reads `description` (`ChecklistCreator.swift:38-43`).
- **relativeDate → dueDateComponents**: single arithmetic `ChecklistItem.dueDateComponents(today:calendar:)` (`ChecklistItem+DueDate.swift:10-20`) — nil for no date, `relativeDate` 0=today/1=tomorrow/negative past, keeps only `[.year,.month,.day]` (no time-of-day), nil on failed day-add. Applied in both paths (`ChecklistReminders.swift:29` + `EventKitReminderDestination.swift:41-43`; `ChecklistCreator.swift:39-41` + `ReminderCreating.swift:38`). Item sync clocks (`titleRevision`/`descriptionRevision`/`relativeDateRevision`, `Checklist.swift:39-48`) are sync-only, never copied to reminders.
- **destinationListIdentifier → reminder.calendar**: only Path A. Pre-loop resolution `ReminderListsSnapshot.resolve` (`ReminderDestinationTargeting.swift:31-37`) + adapter re-resolve by id with TOCTOU throw (`EventKitReminderDestination.swift:33-35,40`). List options from `eventStore.calendars(for: .reminder)` with non-empty identifiers (`:22-26`). Picker writes via `store.setDestination` (`ChecklistStore.swift:239-244`), fed by `ChecklistDetailView.swift:200-216,222-232`. **Ignored in Path B** — `EventKitReminderCreator.create` always uses `defaultCalendarForNewReminders()` (`ReminderCreating.swift:37`); `ChecklistCreator` never reads it.
- **Where a setting exists but is not copied**: Path B drops both `description` and `destinationListIdentifier`; whitespace-only description intentionally nil (`ChecklistRemindersTests.swift:126`); blank titles produce no reminder; missing named destination → `.destinationMissing` zero-created; list deleted mid-loop → partial-creation throw (`EventKitReminderDestination.swift:53-59`).

## Cross-Cutting Observations

- **One production run path, one legacy**: only `ChecklistReminders` + `EventKitReminderDestination` is reachable from the UI (`ContentView.swift:382`); `ChecklistCreator`/`ReminderCreating` exist in Core but are constructed only by tests/`AppEnvironment` today. Any reminder-creating feature should target the production seam (`ReminderDestinationTargeting`, `ReminderDestinationTargeting.swift:83-88`).
- **Enums as outcomes, one thrown error**: all flows return value enums with pre-baked `errorMessage`/`message` text; the single mid-loop throw (`ReminderDestinationError.listMissing`) exists deliberately to distinguish TOCTOU partial failure from pre-loop `.destinationMissing` (`EventKitReminderDestination.swift:56-57` comment). Partial creation is represented today only as `.failed` with no count.
- **Identity keyed by UUID everywhere**: checklist id is the stable merge key across rename and sync; `calendarIdentifier` is the stable destination key across list renames (unlike titles) — both are `file:line`-backed in Q2/Q3.
- **No existing external/dispatch input surface**: the app has no URL/intent/notification handler of any kind (Q4); the only out-of-process channels are the watch's `WCSession` user-info transfer and the KVS observer. App Intents will be the first such surface.
- **Out-of-repo prior art (sibling repo, verified on disk)**: `/Users/vardy/dev/SingleThread/SingleThreadCore/Sources/SingleThreadCore/ReminderIntents.swift` defines `CompleteReminderIntent`/`SkipReminderIntent` as `public struct X: AppIntent` with `title: LocalizedStringResource`, `isDiscoverable = false`, `@MainActor public func perform() async throws -> some IntentResult`, each constructing a fresh store per perform. The same repo uses `EKEventStore.authorizationStatus(for: .reminder)` (`.fullAccess` vs `.noAccess`) to pre-check permission before any access request, and never calls `requestAccess()` from intent/widget surfaces (no prompt possible there) — this is the designated reference implementation for Reminders/EventKit work per the repo AGENTS.md.

## Open Areas

- **App Intents framework mechanics are not in this codebase**: how intents are declared (file/manifest vs code), how an `AppEntity` parameter is declared/discovered, how `perform()` results are shaped, and where the dispatch entry point lives are all absent from CheckStitch source. The SingleThread `AppIntent` structs above are the only on-machine precedent. The design phase must establish the framework surface (declaration, registration, dispatch) — the swiftui-sdk skill's compile-verify approach applies (the compiler is the oracle for whether an API exists).
- **Authorization status pre-check**: CheckStitch's run path only has `requestAccess()` → `Bool` (`EventKitReminderDestination.swift:16-18`); it never reads an authorization-status API before requesting. Whether the platform exposes a status-only read (SingleThread's `authorizationStatus(for: .reminder)`) usable before creation is unverified in this repo's SDK surface.
- **Dispatch-time lifecycle**: no code path exists for receiving an external invocation while the app is backgrounded or cold; how MyApp's scene/task lifecycle (`MyApp.swift:38-80`) interacts with a headless intent dispatch is unexplored.
- **Line-number deltas**: two researchers cited earlier-revision line numbers for `ContentView.swift`; numbers in this document were re-verified against the current files (`ContentView.swift:373-395`, `EventKitReminderDestination.swift:16-48,53-59`, `ChecklistReminders.swift:16-40`, `ReminderDestinationTargeting.swift:31-37,58-74,83-88`).
